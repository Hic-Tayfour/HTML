5 - Métodos de Reamostragem

Os métodos de reamostragem são uma ferramenta indispensável na estatística moderna. Eles envolvem a repetida extração de amostras de um conjunto de treinamento e o ajuste de um modelo de interesse em cada amostra para obter informações adicionais sobre o modelo ajustado. Por exemplo, para estimar a variabilidade de um ajuste de regressão linear, podemos repetidamente extrair diferentes amostras dos dados de treinamento, ajustar uma regressão linear a cada nova amostra e, em seguida, examinar a extensão das diferenças entre os ajustes resultantes. Tal abordagem pode nos permitir obter informações que não estariam disponíveis ajustando o modelo apenas uma vez usando a amostra de treinamento original.

As abordagens de reamostragem podem ser computacionalmente caras, pois envolvem o ajuste do mesmo método estatístico múltiplas vezes usando diferentes subconjuntos dos dados de treinamento. No entanto, devido aos recentes avanços no poder de computação, os requisitos computacionais dos métodos de reamostragem geralmente não são proibitivos. Neste capítulo, discutimos dois dos métodos de reamostragem mais comumente usados, a validação cruzada e o bootstrap. Ambos os métodos são ferramentas importantes na aplicação prática de muitos procedimentos de aprendizado estatístico. Por exemplo, a validação cruzada pode ser usada para estimar o erro de teste associado a um determinado método de aprendizado estatístico para avaliar seu desempenho ou para selecionar o nível apropriado de flexibilidade. O processo de avaliar o desempenho de um modelo é conhecido como avaliação de modelo, enquanto o processo de selecionar o nível adequado de flexibilidade para um modelo é conhecido como seleção de modelo. O bootstrap é usado em vários contextos, mais comumente para fornecer uma medida de precisão de uma estimativa de parâmetro ou de um determinado método de aprendizado estatístico.

5.1 - Validação Cruzada

No Capítulo 2, discutimos a distinção entre a taxa de erro de teste e a taxa de erro de treinamento. O erro de teste é o erro médio que resulta do uso de um método de aprendizado estatístico para prever a resposta em uma nova observação — ou seja, uma medição que não foi usada no treinamento do método. Dado um conjunto de dados, o uso de um determinado método de aprendizado estatístico é justificado se resultar em um baixo erro de teste. O erro de teste pode ser facilmente calculado se um conjunto de teste designado estiver disponível. Infelizmente, isso geralmente não é o caso. Em contraste, o erro de treinamento pode ser facilmente calculado aplicando o método de aprendizado estatístico às observações usadas no treinamento. Mas, como vimos no Capítulo 2, a taxa de erro de treinamento muitas vezes é bastante diferente da taxa de erro de teste e, em particular, a primeira pode subestimar dramaticamente a última.

Na ausência de um conjunto de teste designado muito grande que possa ser usado para estimar diretamente a taxa de erro de teste, uma série de técnicas podem ser usadas para estimar essa quantidade usando os dados de treinamento disponíveis. Alguns métodos fazem um ajuste matemático na taxa de erro de treinamento para estimar a taxa de erro de teste. Essas abordagens são discutidas no Capítulo 6. Nesta seção, consideramos uma classe de métodos que estimam a taxa de erro de teste excluindo um subconjunto das observações de treinamento do processo de ajuste e, em seguida, aplicando o método de aprendizado estatístico a essas observações excluídas.

Nas Seções 5.1.1–5.1.4, para simplificar, assumimos que estamos interessados em realizar regressão com uma resposta quantitativa. Na Seção 5.1.5, consideramos o caso da classificação com uma resposta qualitativa. Como veremos, os conceitos-chave permanecem os mesmos, independentemente de a resposta ser quantitativa ou qualitativa.

5.1.1 - A Abordagem do Conjunto de Validação

Suponha que gostaríamos de estimar o erro de teste associado ao ajuste de um determinado método de aprendizado estatístico em um conjunto de observações. A abordagem do conjunto de validação, mostrada na Figura 5.1, é uma estratégia muito simples para essa tarefa. Ela envolve dividir aleatoriamente o conjunto disponível de observações em duas partes, um conjunto de treinamento e um conjunto de validação ou conjunto de retenção. O modelo é ajustado no conjunto de treinamento, e o modelo ajustado é usado para prever as respostas das observações no conjunto de validação. A taxa de erro do conjunto de validação resultante—tipicamente avaliada usando MSE no caso de uma resposta quantitativa—fornece uma estimativa da taxa de erro de teste.

Ilustramos a abordagem do conjunto de validação no conjunto de dados Auto. Recorde do Capítulo 3 que parece haver uma relação não linear entre mpg e horsepower, e que um modelo que prediz mpg usando horsepower e horsepower^2 dá resultados melhores do que um modelo que usa apenas um termo linear. É natural perguntar se um ajuste cúbico ou de ordem superior poderia fornecer resultados ainda melhores. Respondemos a essa pergunta no Capítulo 3 observando os p-valores associados a um termo cúbico e termos polinomiais de ordem superior em uma regressão linear. Mas também poderíamos responder a essa pergunta usando o método de validação. Dividimos aleatoriamente as 392 observações em dois conjuntos, um conjunto de treinamento contendo 196 pontos de dados e um conjunto de validação contendo as 196 observações restantes. As taxas de erro do conjunto de validação resultantes do ajuste de vários modelos de regressão no conjunto de treinamento e da avaliação de seu desempenho no conjunto de validação, usando MSE como medida de erro do conjunto de validação, são mostradas no painel esquerdo da Figura 5.2. O MSE do conjunto de validação para o ajuste quadrático é consideravelmente menor do que para o ajuste linear. No entanto, o MSE do conjunto de validação para o ajuste cúbico é ligeiramente maior do que para o ajuste quadrático. Isso implica que incluir um termo cúbico na regressão não leva a uma melhor previsão do que simplesmente usar um termo quadrático.


Lembre-se de que, para criar o painel esquerdo da Figura 5.2, dividimos aleatoriamente o conjunto de dados em duas partes, um conjunto de treinamento e um conjunto de validação. Se repetirmos o processo de dividir aleatoriamente o conjunto de amostras em duas partes, obteremos uma estimativa um pouco diferente do MSE de teste. Como ilustração, o painel direito da Figura 5.2 exibe dez diferentes curvas de MSE do conjunto de validação a partir do conjunto de dados Auto, produzidas usando dez divisões aleatórias diferentes das observações em conjuntos de treinamento e validação. Todas as dez curvas indicam que o modelo com um termo quadrático tem um MSE do conjunto de validação dramaticamente menor do que o modelo com apenas um termo linear. Além disso, todas as dez curvas indicam que não há muito benefício em incluir termos polinomiais cúbicos ou de ordem superior no modelo. Mas vale notar que cada uma das dez curvas resulta em uma estimativa de MSE de teste diferente para cada um dos dez modelos de regressão considerados. E não há consenso entre as curvas sobre qual modelo resulta no menor MSE do conjunto de validação. Com base na variabilidade entre essas curvas, tudo o que podemos concluir com confiança é que o ajuste linear não é adequado para esses dados.

A abordagem do conjunto de validação é conceitualmente simples e fácil de implementar. Mas ela tem duas desvantagens potenciais:

  1. Como mostrado no painel direito da Figura 5.2, a estimativa de validação da taxa de erro de teste pode ser altamente variável, dependendo precisamente de quais observações estão incluídas no conjunto de treinamento e quais observações estão incluídas no conjunto de validação.
  2. Na abordagem de validação, apenas um subconjunto das observações—aquelas que estão incluídas no conjunto de treinamento em vez do conjunto de validação—é usado para ajustar o modelo. Como os métodos estatísticos tendem a ter um desempenho pior quando treinados em menos observações, isso sugere que a taxa de erro do conjunto de validação pode tender a superestimar a taxa de erro de teste para o modelo ajustado em todo o conjunto de dados.


Nas próximas subseções, apresentaremos a validação cruzada, um refinamento da abordagem do conjunto de validação que aborda essas duas questões.

5.1.2 - Validação Cruzada de Deixar-Um-Fora

A validação cruzada leave-one-out (LOOCV) está intimamente relacionada à abordagem do conjunto de validação da Seção 5.1.1, mas tenta abordar as desvantagens desse método.

Assim como a abordagem do conjunto de validação, a LOOCV envolve dividir o conjunto de observações em duas partes. No entanto, em vez de criar dois subconjuntos de tamanho comparável, uma única observação \((x_1, y_1)\) é usada para o conjunto de validação, e as observações restantes \(\{(x_2, y_2),...,(x_n, y_n)\}\) compõem o conjunto de treinamento. O método de aprendizado estatístico é ajustado nas \(n - 1\) observações de treinamento, e uma previsão \(\hat{y}_1\) é feita para a observação excluída, usando seu valor \(x_1\). Como \((x_1, y_1)\) não foi usado no processo de ajuste, \(MSE_1 = (y_1 - \hat{y}_1)^2\) fornece uma estimativa aproximadamente não tendenciosa do erro de teste. Mas, embora o \(MSE_1\) seja não tendencioso para o erro de teste, é uma estimativa ruim porque é altamente variável, já que é baseada em uma única observação \((x_1, y_1)\).


Podemos repetir o procedimento selecionando \((x_2, y_2)\) para os dados de validação, treinando o procedimento de aprendizado estatístico nas \(n - 1\) observações \(\{(x_1, y_1),(x_3, y_3),...,(x_n, y_n)\}\), e calculando \(MSE_2 = (y_2 - \hat{y}_2)^2\). Repetir essa abordagem \(n\) vezes produz \(n\) erros quadráticos, \(MSE_1,..., MSE_n\). A estimativa LOOCV para o \(MSE\) de teste é a média dessas \(n\) estimativas de erro de teste: \[ CV(n) = \frac{1}{n} \sum_{i=1}^{n} MSE_i. \]

A LOOCV tem algumas vantagens importantes sobre a abordagem do conjunto de validação. Primeiro, ela possui muito menos viés. Na LOOCV, ajustamos repetidamente o método de aprendizado estatístico usando conjuntos de treinamento que contêm \(n - 1\) observações, quase tantas quanto estão no conjunto de dados inteiro. Isso contrasta com a abordagem do conjunto de validação, na qual o conjunto de treinamento geralmente contém cerca de metade do tamanho do conjunto de dados original. Consequentemente, a abordagem LOOCV tende a não superestimar a taxa de erro de teste tanto quanto a abordagem do conjunto de validação. Segundo, em contraste com a abordagem de validação que produzirá resultados diferentes quando aplicada repetidamente devido à aleatoriedade nas divisões do conjunto de treinamento e validação, realizar a LOOCV múltiplas vezes sempre produzirá os mesmos resultados: não há aleatoriedade nas divisões do conjunto de treinamento e validação.

Usamos a LOOCV no conjunto de dados Auto para obter uma estimativa do \(MSE\) do conjunto de teste que resulta do ajuste de um modelo de regressão linear para prever mpg usando funções polinomiais de potência. Os resultados são mostrados no painel esquerdo da Figura 5.4.

A LOOCV tem o potencial de ser cara de implementar, pois o modelo deve ser ajustado \(n\) vezes. Isso pode ser muito demorado se \(n\) for grande e se cada modelo individual for lento de ajustar. Com a regressão linear ou polinomial dos mínimos quadrados, um atalho incrível torna o custo da LOOCV o mesmo que o de um único ajuste de modelo! A fórmula a seguir se mantém: \[ CV(n) = \frac{1}{n} \sum_{i=1}^{n} \left(\frac{y_i - \hat{y}_i}{1 - h_i}\right)^2, \] onde \(\hat{y}_i\) é o \(i\)-ésimo valor ajustado do ajuste original dos mínimos quadrados, e \(h_i\) é a alavancagem definida em (3.37) na página 99. Isso é como o \(MSE\) comum, exceto que o resíduo \(i\) é dividido por \(1 - h_i\). A alavancagem está entre \(1/n\) e 1, e reflete a quantidade que uma observação influencia seu próprio ajuste. Assim, os resíduos para pontos de alta alavancagem são inflacionados nesta fórmula pela quantidade exata para que esta igualdade se mantenha.

A LOOCV é um método muito geral e pode ser usado com qualquer tipo de modelagem preditiva. Por exemplo, poderíamos usá-la com regressão logística ou análise discriminante linear, ou qualquer um dos métodos discutidos nos capítulos posteriores. A fórmula mágica (5.2) não se mantém em geral, caso em que o modelo deve ser ajustado \(n\) vezes.


5.1.3 - Validação Cruzada k-Fold

Uma alternativa à LOOCV é a validação cruzada k-fold (k-fold CV). Essa abordagem envolve dividir aleatoriamente o conjunto de observações em k grupos, ou dobras, de tamanho aproximadamente igual. A primeira dobra é tratada como um conjunto de validação, e o método é ajustado nas k − 1 dobras restantes. O erro quadrático médio, \(MSE_1\), é então calculado nas observações da dobra excluída. Esse procedimento é repetido k vezes; cada vez, um grupo diferente de observações é tratado como conjunto de validação. Esse processo resulta em k estimativas do erro de teste, \(MSE_1, MSE_2,..., MSE_k\). A estimativa k-fold CV é calculada pela média desses valores: \[ CV(k) = \frac{1}{k} \sum_{i=1}^{k} MSE_i. \] A Figura 5.5 ilustra a abordagem k-fold CV.

Não é difícil ver que a LOOCV é um caso especial de k-fold CV em que k é igual a n. Na prática, geralmente se realiza k-fold CV usando k = 5 ou k = 10. Qual é a vantagem de usar k = 5 ou k = 10 em vez de k = n? A vantagem mais óbvia é computacional. A LOOCV requer ajustar o método de aprendizado estatístico n vezes. Isso tem o potencial de ser computacionalmente caro (exceto para modelos lineares ajustados por mínimos quadrados, caso em que a fórmula (5.2) pode ser usada). Mas a validação cruzada é uma abordagem muito geral que pode ser aplicada a quase qualquer método de aprendizado estatístico. Alguns métodos de aprendizado estatístico têm procedimentos de ajuste computacionalmente intensivos, e assim realizar a LOOCV pode apresentar problemas computacionais, especialmente se n for extremamente grande. Em contraste, realizar 10-fold CV requer ajustar o procedimento de aprendizado apenas dez vezes, o que pode ser muito mais viável. Como veremos na Seção 5.1.4, também pode haver outras vantagens não computacionais em realizar 5-fold ou 10-fold CV, que envolvem o trade-off viés-variância.


O painel direito da Figura 5.4 exibe nove estimativas diferentes de 10-fold CV para o conjunto de dados Auto, cada uma resultante de uma divisão aleatória diferente das observações em dez dobras. Como podemos ver na figura, há alguma variabilidade nas estimativas de CV como resultado da variabilidade em como as observações são divididas em dez dobras. Mas essa variabilidade é tipicamente muito menor do que a variabilidade nas estimativas de erro de teste que resulta da abordagem do conjunto de validação (painel direito da Figura 5.2).

Quando examinamos dados reais, não conhecemos o verdadeiro MSE de teste, e assim é difícil determinar a precisão da estimativa de validação cruzada. No entanto, se examinarmos dados simulados, podemos calcular o verdadeiro MSE de teste, e assim avaliar a precisão dos nossos resultados de validação cruzada. Na Figura 5.6, plotamos as estimativas de validação cruzada e as taxas de erro de teste verdadeiras que resultam da aplicação de splines suavizantes aos conjuntos de dados simulados ilustrados nas Figuras 2.9–2.11 do Capítulo 2. O verdadeiro MSE de teste é exibido em azul. As linhas pretas tracejadas e laranjas sólidas mostram, respectivamente, as estimativas LOOCV e 10-fold CV. Em todos os três gráficos, as duas estimativas de validação cruzada são muito semelhantes. No painel direito da Figura 5.6, o verdadeiro MSE de teste e as curvas de validação cruzada são quase idênticos. No painel central da Figura 5.6, os dois conjuntos de curvas são semelhantes nos níveis mais baixos de flexibilidade, enquanto as curvas de CV superestimam o MSE do conjunto de teste para níveis mais altos de flexibilidade. No painel esquerdo da Figura 5.6, as curvas de CV têm a forma geral correta, mas subestimam o verdadeiro MSE de teste.

Quando realizamos a validação cruzada, nosso objetivo pode ser determinar o quão bem um determinado procedimento de aprendizado estatístico pode ser esperado para performar em dados independentes; nesse caso, a estimativa real do MSE de teste é de interesse. Mas, em outros momentos, estamos interessados apenas na localização do ponto mínimo na curva estimada do MSE de teste. Isso porque podemos estar realizando validação cruzada em um número de métodos de aprendizado estatístico, ou em um único método usando diferentes níveis de flexibilidade, a fim de identificar o método que resulta no menor erro de teste. Para esse propósito, a localização do ponto mínimo na curva estimada do MSE de teste é importante, mas o valor real do MSE de teste estimado não é. Descobrimos na Figura 5.6 que, apesar de às vezes subestimarem o verdadeiro MSE de teste, todas as curvas de CV chegam perto de identificar o nível correto de flexibilidade - ou seja, o nível de flexibilidade correspondente ao menor MSE de teste.

5.1.4 - Compromisso Viés-Variância para Validação Cruzada k-Fold

Mencionamos na Seção 5.1.3 que a k-fold CV com \(k<n\) tem uma vantagem computacional em relação à LOOCV. Mas, deixando de lado as questões computacionais, uma vantagem menos óbvia, mas potencialmente mais importante, da k-fold CV é que ela frequentemente fornece estimativas mais precisas da taxa de erro de teste do que a LOOCV. Isso tem a ver com o trade-off viés-variância.

Foi mencionado na Seção 5.1.1 que a abordagem do conjunto de validação pode levar a superestimativas da taxa de erro de teste, uma vez que, nessa abordagem, o conjunto de treinamento usado para ajustar o método de aprendizado estatístico contém apenas metade das observações do conjunto de dados completo. Usando essa lógica, não é difícil ver que a LOOCV dará estimativas aproximadamente não tendenciosas do erro de teste, uma vez que cada conjunto de treinamento contém \(n−1\) observações, quase tantas quanto o número de observações no conjunto de dados completo. E realizar k-fold CV com, por exemplo, \(k = 5\) ou \(k = 10\) levará a um nível intermediário de viés, uma vez que cada conjunto de treinamento contém aproximadamente \((k−1)n/k\) observações - menos do que na abordagem LOOCV, mas substancialmente mais do que na abordagem do conjunto de validação. Portanto, do ponto de vista da redução do viés, é claro que a LOOCV é preferível à k-fold CV.

No entanto, sabemos que o viés não é a única preocupação em um procedimento de estimativa; também devemos considerar a variância do procedimento. Acontece que a LOOCV tem uma variância maior do que a k-fold CV com \(k<n\). Por que isso acontece? Quando realizamos a LOOCV, estamos, na verdade, fazendo a média das saídas de \(n\) modelos ajustados, cada um treinado em um conjunto de observações quase idêntico; portanto, essas saídas são altamente (positivamente) correlacionadas entre si. Em contraste, quando realizamos a k-fold CV com \(k<n\), estamos fazendo a média das saídas de \(k\) modelos ajustados que são um pouco menos correlacionados entre si, uma vez que a sobreposição entre os conjuntos de treinamento em cada modelo é menor. Como a média de muitas quantidades altamente correlacionadas tem maior variância do que a média de muitas quantidades que não são tão altamente correlacionadas, a estimativa do erro de teste resultante da LOOCV tende a ter maior variância do que a estimativa do erro de teste resultante da k-fold CV.

Para resumir, há um trade-off viés-variância associado à escolha de \(k\) na validação cruzada k-fold. Tipicamente, considerando essas considerações, realiza-se a validação cruzada k-fold usando \(k = 5\) ou \(k = 10\), pois esses valores têm mostrado empiricamente fornecer estimativas de taxa de erro de teste que não sofrem nem de viés excessivamente alto nem de variância muito alta.

5.1.5 - Validação Cruzada em Problemas de Classificação

Até agora neste capítulo, ilustramos o uso da validação cruzada no cenário de regressão onde o resultado \(Y\) é quantitativo, e, portanto, usamos o MSE para quantificar o erro de teste. No entanto, a validação cruzada também pode ser uma abordagem muito útil no cenário de classificação quando \(Y\) é qualitativo. Nesse cenário, a validação cruzada funciona exatamente como descrito anteriormente neste capítulo, exceto que, em vez de usar o MSE para quantificar o erro de teste, usamos o número de observações classificadas incorretamente. Por exemplo, no cenário de classificação, a taxa de erro da LOOCV assume a forma

\[CV(n) = \frac{1}{n} \sum_{i=1}^{n} Err_i,\]

onde \(Err_i = I(y_i \ne \hat{y_i})\). As taxas de erro da k-fold CV e do conjunto de validação são definidas de forma análoga.

Como exemplo, ajustamos vários modelos de regressão logística aos dados de classificação bidimensionais mostrados na Figura 2.13. No painel superior esquerdo da Figura 5.7, a linha preta sólida mostra a fronteira de decisão estimada resultante do ajuste de um modelo de regressão logística padrão a este conjunto de dados. Como estes são dados simulados, podemos calcular a verdadeira taxa de erro de teste, que assume um valor de 0.201, sendo substancialmente maior que a taxa de erro de Bayes de 0.133. Claramente, a regressão logística não tem flexibilidade suficiente para modelar a fronteira de decisão de Bayes nesse cenário. Podemos facilmente estender a regressão logística para obter uma fronteira de decisão não linear usando funções polinomiais dos preditores, como fizemos no cenário de regressão na Seção 3.3.2. Por exemplo, podemos ajustar um modelo de regressão logística quadrática, dado por

\[\log \left( \frac{p}{1 - p} \right) = \beta_0 + \beta_1X_1 + \beta_2X_1^2 + \beta_3X_2 + \beta_4X_2^2.\]

O painel superior direito da Figura 5.7 exibe a fronteira de decisão resultante, que agora é curvada. No entanto, a taxa de erro de teste melhorou apenas ligeiramente, para 0.197. Uma melhoria muito maior é aparente no painel inferior esquerdo da Figura 5.7, no qual ajustamos um modelo de regressão logística envolvendo polinômios cúbicos dos preditores. Agora a taxa de erro de teste diminuiu para 0.160. Usar um polinômio quártico (inferior direito) aumenta ligeiramente o erro de teste.

Na prática, para dados reais, a fronteira de decisão de Bayes e as taxas de erro de teste são desconhecidas. Então, como podemos decidir entre os quatro modelos de regressão logística exibidos na Figura 5.7? Podemos usar a validação cruzada para tomar essa decisão. O painel esquerdo da Figura 5.8 exibe em preto as taxas de erro da CV de 10 partes resultantes do ajuste de dez modelos de regressão logística aos dados, usando funções polinomiais dos preditores até a décima ordem. Os erros de teste reais são mostrados em marrom, e os erros de treinamento são mostrados em azul. Como vimos anteriormente, o erro de treinamento tende a diminuir à medida que a flexibilidade do ajuste aumenta. (A figura indica que, embora a taxa de erro de treinamento não diminua de forma monótona, tende a diminuir como um todo à medida que a complexidade do modelo aumenta.) Em contraste, o erro de teste exibe uma forma característica em U. A taxa de erro da CV de 10 partes fornece uma aproximação bastante boa para a taxa de erro de teste. Embora subestime um pouco a taxa de erro, ela atinge um mínimo quando polinômios de quarta ordem são usados, o que está muito próximo do mínimo da curva de teste, que ocorre quando polinômios de terceira ordem são usados. De fato, usar polinômios de quarta ordem provavelmente levaria a um bom desempenho no conjunto de testes, pois a taxa de erro de teste real é aproximadamente a mesma para polinômios de terceira, quarta, quinta e sexta ordens.

O painel direito da Figura 5.8 exibe as mesmas três curvas usando a abordagem KNN para classificação, em função do valor de \(K\) (que neste contexto indica o número de vizinhos usados no classificador KNN, em vez do número de partes da CV usadas). Novamente, a taxa de erro de treinamento diminui à medida que o método se torna mais flexível, e vemos que a taxa de erro de treinamento não pode ser usada para selecionar o valor ótimo para \(K\). Embora a curva de erro da validação cruzada subestime ligeiramente a taxa de erro de teste, ela atinge um mínimo muito próximo do melhor valor para \(K\).

5.2 - O Bootstrap

O bootstrap é uma ferramenta estatística amplamente aplicável e extremamente poderosa que pode ser usada para quantificar a incerteza associada a um dado estimador ou método de aprendizado estatístico. Como exemplo simples, o bootstrap pode ser usado para estimar os erros padrão dos coeficientes de um ajuste de regressão linear. No caso específico da regressão linear, isso não é particularmente útil, pois vimos no Capítulo 3 que softwares estatísticos padrão, como o R, fornecem esses erros padrão automaticamente. No entanto, o poder do bootstrap reside no fato de que ele pode ser facilmente aplicado a uma ampla gama de métodos de aprendizado estatístico, incluindo alguns para os quais uma medida de variabilidade é, de outra forma, difícil de obter e não é fornecida automaticamente pelos softwares estatísticos.

Nesta seção, ilustramos o bootstrap em um exemplo simples no qual desejamos determinar a melhor alocação de investimento sob um modelo simples. Na Seção 5.3, exploramos o uso do bootstrap para avaliar a variabilidade associada aos coeficientes de regressão em um modelo linear ajustado.

Suponha que desejemos investir uma quantia fixa de dinheiro em dois ativos financeiros que geram retornos de \(X\) e \(Y\), respectivamente, onde \(X\) e \(Y\) são quantidades aleatórias. Investiremos uma fração \(\alpha\) do nosso dinheiro em \(X\), e investiremos o restante \(1 - \alpha\) em \(Y\). Como há variabilidade associada aos retornos desses dois ativos, desejamos escolher \(\alpha\) para minimizar o risco total, ou a variância, do nosso investimento. Em outras palavras, queremos minimizar \(Var(\alpha X + (1 - \alpha) Y)\). Pode-se mostrar que o valor que minimiza o risco é dado por

\[\alpha = \frac{\sigma^2_Y - \sigma_{XY}}{\sigma^2_X + \sigma^2_Y - 2\sigma_{XY}},\]

onde \(\sigma^2_X = Var(X)\), \(\sigma^2_Y = Var(Y)\), e \(\sigma_{XY} = Cov(X, Y)\).

Na realidade, as quantidades \(\sigma^2_X\), \(\sigma^2_Y\) e \(\sigma_{XY}\) são desconhecidas. Podemos calcular estimativas para essas quantidades, \(\hat{\sigma}^2_X\), \(\hat{\sigma}^2_Y\) e \(\hat{\sigma}_{XY}\), usando um conjunto de dados que contém medições passadas de \(X\) e \(Y\). Podemos então estimar o valor de \(\alpha\) que minimiza a variância do nosso investimento usando

\[\hat{\alpha} = \frac{\hat{\sigma}^2_Y - \hat{\sigma}_{XY}}{\hat{\sigma}^2_X + \hat{\sigma}^2_Y - 2\hat{\sigma}_{XY}}.\]

A Figura 5.9 ilustra essa abordagem para estimar \(\alpha\) em um conjunto de dados simulado. Em cada painel, simulamos 100 pares de retornos para os investimentos \(X\) e \(Y\). Usamos esses retornos para estimar \(\sigma^2_X\), \(\sigma^2_Y\) e \(\sigma_{XY}\), que então substituímos em (5.7) para obter estimativas para \(\alpha\). O valor de \(\hat{\alpha}\) resultante de cada conjunto de dados simulado varia de 0.532 a 0.657.

É natural desejar quantificar a precisão da nossa estimativa de \(\alpha\). Para estimar o desvio padrão de \(\hat{\alpha}\), repetimos o processo de simular 100 observações emparelhadas de \(X\) e \(Y\), e estimar \(\alpha\) usando (5.7), 1.000 vezes. Obtivemos assim 1.000 estimativas para \(\alpha\), que podemos chamar de \(\hat{\alpha}_1, \hat{\alpha}_2,..., \hat{\alpha}_{1.000}\). O painel esquerdo da Figura 5.10 exibe um histograma das estimativas resultantes. Para essas simulações, os parâmetros foram definidos como \(\sigma^2_X = 1\), \(\sigma^2_Y = 1.25\) e \(\sigma_{XY} = 0.5\), e sabemos que o valor verdadeiro de \(\alpha\) é 0.6. Indicamos esse valor usando uma linha vertical sólida no histograma. A média de todas as 1.000 estimativas para \(\alpha\) é

\[\bar{\alpha} = \frac{1}{1.000} \sum_{r=1}^{1.000} \hat{\alpha}_r = 0.5996,\]

muito próximo de \(\alpha = 0.6\), e o desvio padrão das estimativas é

\[SE(\hat{\alpha}) \approx 0.083.\]

Isso nos dá uma boa ideia da precisão de \(\hat{\alpha}\): \(SE(\hat{\alpha}) \approx 0.083\). Portanto, em termos gerais, para uma amostra aleatória da população, esperaríamos que \(\hat{\alpha}\) diferisse de \(\alpha\) em aproximadamente 0.08, em média.

Na prática, no entanto, o procedimento para estimar \(SE(\hat{\alpha})\) descrito acima não pode ser aplicado, pois para dados reais não podemos gerar novas amostras da população original. No entanto, a abordagem bootstrap nos permite usar um computador para emular o processo de obtenção de novos conjuntos de amostras, de modo que possamos estimar a variabilidade de \(\hat{\alpha}\) sem gerar amostras adicionais. Em vez de obter repetidamente conjuntos de dados independentes da população, obtemos conjuntos de dados distintos amostrando repetidamente observações do conjunto de dados original.

Essa abordagem é ilustrada na Figura 5.11 em um conjunto de dados simples, que chamamos de \(Z\), que contém apenas \(n = 3\) observações. Selecionamos aleatoriamente \(n\) observações do conjunto de dados para produzir um conjunto de dados bootstrap, \(Z^*_1\). A amostragem é realizada com reposição, o que significa que a mesma observação pode ocorrer mais de uma vez no conjunto de dados bootstrap. Neste exemplo, \(Z^*_1\) contém a terceira observação duas vezes, a primeira observação uma vez e nenhuma ocorrência da segunda observação. Note que se uma observação está contida em \(Z^*_1\), então tanto seus valores de \(X\) quanto de \(Y\) são incluídos. Podemos usar \(Z^*_1\) para produzir uma nova estimativa bootstrap para \(\alpha\), que chamamos de \(\hat{\alpha}^*_1\). Esse procedimento é repetido \(B\) vezes para um grande valor de \(B\), a fim de produzir \(B\) conjuntos de dados bootstrap distintos, \(Z^*_1, Z^*_2,..., Z^*_B\), e \(B\) estimativas correspondentes de \(\alpha\), \(\hat{\alpha}^*_1, \hat{\alpha}^*_2,..., \hat{\alpha}^*_B\). Podemos calcular o erro padrão dessas estimativas bootstrap usando a fórmula

\[SE_B(\hat{\alpha}) = \sqrt{\frac{1}{B - 1} \sum_{r=1}^{B} \left(\hat{\alpha}^*_r - \frac{1}{B} \sum_{r'=1}^{B} \hat{\alpha}^*_{r'}\right)^2}.\]

Isso serve como uma estimativa do erro padrão de \(\hat{\alpha}\) estimado a partir do conjunto de dados original.

A abordagem bootstrap é ilustrada no painel central da Figura 5.10, que exibe um histograma de 1.000 estimativas bootstrap de \(\alpha\), cada uma calculada usando um conjunto de dados bootstrap distinto. Este painel foi construído com base em um único conjunto de dados e, portanto, poderia ser criado usando dados reais. Note que o histograma se parece muito com o painel esquerdo, que exibe o histograma idealizado das estimativas de \(\alpha\) obtido gerando 1.000 conjuntos de dados simulados da população verdadeira. Em particular, a estimativa bootstrap \(SE(\hat{\alpha})\) de (5.8) é 0.087, muito próxima da estimativa de 0.083 obtida usando 1.000 conjuntos de dados simulados. O painel direito exibe as informações dos painéis central e esquerdo de forma diferente, via boxplots das estimativas para \(\alpha\) obtidas gerando 1.000 conjuntos de dados simulados da população verdadeira e usando a abordagem bootstrap. Novamente, os boxplots têm distribuições semelhantes, indicando que a abordagem bootstrap pode ser usada para estimar efetivamente a variabilidade associada a \(\hat{\alpha}\).

5.3 - Laboratório: Validação Cruzada e Bootstrap

Neste laboratório, exploramos as técnicas de reamostragem abordadas neste capítulo. Alguns dos comandos neste laboratório podem demorar um pouco para serem executados em seu computador.

5.3.1 - A Abordagem do Conjunto de Validação

Exploramos o uso da abordagem do conjunto de validação para estimar as taxas de erro de teste resultantes do ajuste de vários modelos lineares no conjunto de dados Auto.

Começamos usando a função sample() para dividir o conjunto de observações em duas metades, selecionando um subconjunto aleatório de 196 observações das 392 observações originais. Referimos-nos a essas observações como o conjunto de treinamento.

library(ISLR2)

set.seed(1)

train <- sample(392, 196)

(Aqui usamos um atalho no comando sample; veja ?sample para detalhes.) Em seguida, usamos a opção subset em lm() para ajustar uma regressão linear usando apenas as observações correspondentes ao conjunto de treinamento.

lm.fit <- lm(mpg ~ horsepower, data = Auto, subset = train)

Agora usamos a função predict() para estimar a resposta para todas as 392 observações e usamos a função mean() para calcular o MSE das 196 observações no conjunto de validação. Note que o índice -train abaixo seleciona apenas as observações que não estão no conjunto de treinamento.

attach(Auto)

mean((mpg - predict(lm.fit, Auto))[-train]^2)
[1] 23.26601

Portanto, o MSE de teste estimado para o ajuste de regressão linear é 23,27. Podemos usar a função poly() para estimar o erro de teste para as regressões quadrática e cúbica.

lm.fit2 <- lm(mpg ~poly(horsepower, 2), data= Auto, 
              subset = train)

mean((mpg - predict(lm.fit2, Auto))[-train]^2)
[1] 18.71646
lm.fit3 <- lm(mpg ~poly(horsepower, 3), data= Auto, 
              subset = train)

mean((mpg - predict(lm.fit3, Auto))[-train]^2)
[1] 18.79401

Essas taxas de erro são 18,72 e 18,79, respectivamente. Se escolhermos um conjunto de treinamento diferente, obteremos erros ligeiramente diferentes no conjunto de validação.

set.seed(2)

train <- sample(392, 196)

lm.fit <- lm(mpg ~ horsepower, subset = train)

mean((mpg - predict(lm.fit, Auto))[-train]^2)
[1] 25.72651
lm.fit2 <- lm(mpg ~poly(horsepower, 2), data= Auto, 
              subset = train)

mean((mpg - predict(lm.fit2, Auto))[-train]^2)
[1] 20.43036

mean((mpg - predict(lm.fit3, Auto))[-train]^2)
[1] 20.38533

Usando essa divisão das observações em um conjunto de treinamento e um conjunto de validação, descobrimos que as taxas de erro do conjunto de validação para os modelos com termos lineares, quadráticos e cúbicos são 25,73, 20,43 e 20,39, respectivamente.

Esses resultados são consistentes com nossas descobertas anteriores: um modelo que prevê mpg usando uma função quadrática de potência do motor apresenta um desempenho melhor do que um modelo que envolve apenas uma função linear de potência do motor, e há poucas evidências a favor de um modelo que usa uma função cúbica de potência do motor.

5.3.2 - Validação Cruzada de Deixar-Um-Fora

A estimativa LOOCV pode ser computada automaticamente para qualquer modelo linear generalizado usando as funções glm() e cv.glm(). No laboratório do Capítulo 4, usamos a função glm() para realizar regressão logística passando o argumento family = "binomial". Mas se usarmos glm() para ajustar um modelo sem passar o argumento family, ele realiza regressão linear, assim como a função lm(). Portanto, por exemplo,

glm.fit <- glm(mpg ~ horsepower, data = Auto)

coef(glm.fit)
(Intercept)  horsepower 
 39.9358610  -0.1578447

e

lm.fit <- lm(mpg ~ horsepower, data = Auto)

coef(lm.fit)
(Intercept)  horsepower 
 39.9358610  -0.1578447

produzem modelos de regressão linear idênticos. Neste laboratório, realizaremos a regressão linear usando a função glm() em vez da função lm() porque a primeira pode ser usada junto com cv.glm(). A função cv.glm() faz parte da biblioteca boot.

library(boot)

glm.fit <- glm(mpg ~ horsepower, data = Auto)

cv.err <- cv.glm(Auto, glm.fit)

cv.err$delta
[1] 24.23151 24.23114

A função cv.glm() produz uma lista com vários componentes. Os dois números no vetor delta contêm os resultados da validação cruzada. Nesse caso, os números são idênticos (até duas casas decimais) e correspondem ao estatístico LOOCV dado em (5.1). A seguir, discutimos uma situação em que os dois números diferem. Nossa estimativa de validação cruzada para o erro de teste é aproximadamente 24.23.

Podemos repetir este procedimento para ajustes polinomiais de complexidade crescente. Para automatizar o processo, usamos a função for() para iniciar um loop for() que ajusta iterativamente regressões polinomiais para polinômios de ordem \(i = 1\) a \(i = 10\), calcula o erro de validação cruzada associado e o armazena no \(i\)-ésimo elemento do vetor cv.error. Começamos inicializando o vetor.

cv.error <- rep(0, 10)

for (i in 1:10) {
  glm.fit <- glm(mpg ~ poly(horsepower, i), data = Auto)
  cv.error[i] <- cv.glm(Auto, glm.fit)$delta[1]
}

cv.error
 [1] 24.23151 19.24821 19.33498 19.42443 19.03321 18.97864 18.83305 18.96115
 [9] 19.06863 19.49093

Como na Figura 5.4, observamos uma queda acentuada no MSE estimado do teste entre os ajustes lineares e quadráticos, mas depois não há uma melhoria clara ao usar polinômios de ordem superior.

5.3.3 - Validação Cruzada k-Fold

A função cv.glm() também pode ser usada para implementar a validação cruzada k-fold. Abaixo, usamos \(k = 10\), uma escolha comum para \(k\), no conjunto de dados Auto. Mais uma vez, definimos uma semente aleatória e inicializamos um vetor no qual armazenaremos os erros de validação cruzada correspondentes aos ajustes polinomiais de ordem um a dez.

Observe que o tempo de computação é menor do que o do LOOCV. (Em princípio, o tempo de computação para LOOCV para um modelo linear de mínimos quadrados deve ser mais rápido do que para a validação cruzada k-fold, devido à disponibilidade da fórmula (5.2) para LOOCV; no entanto, infelizmente, a função cv.glm() não faz uso dessa fórmula.) Ainda assim, vemos poucas evidências de que usar termos polinomiais cúbicos ou de ordem superior leva a um erro de teste menor do que simplesmente usar um ajuste quadrático.

Vimos na Seção 5.3.2 que os dois números associados ao delta são essencialmente os mesmos quando o LOOCV é realizado. Quando, em vez disso, realizamos a validação cruzada k-fold, os dois números associados ao delta diferem ligeiramente. O primeiro é a estimativa padrão da validação cruzada k-fold, como em (5.3). O segundo é uma versão corrigida pelo viés. Neste conjunto de dados, as duas estimativas são muito semelhantes.

5.3.4 - O Bootstrap

Ilustramos o uso do bootstrap no exemplo simples da Seção 5.2, bem como em um exemplo envolvendo a estimativa da precisão do modelo de regressão linear no conjunto de dados Auto.

Estimando a Precisão de uma Estatística de Interesse

Uma das grandes vantagens da abordagem bootstrap é que ela pode ser aplicada em quase todas as situações. Não são necessários cálculos matemáticos complicados. Realizar uma análise bootstrap em R envolve apenas dois passos. Primeiro, devemos criar uma função que compute a estatística de interesse. Segundo, usamos a função boot(), que faz parte da biblioteca boot, para realizar o bootstrap, amostrando repetidamente observações do conjunto de dados com reposição.

O conjunto de dados Portfolio no pacote ISLR2 é um dado simulado de 100 pares de retornos, gerado da maneira descrita na Seção 5.2. Para ilustrar o uso do bootstrap neste dado, devemos primeiro criar uma função, alpha.fn(), que recebe como entrada os dados \((X, Y)\), bem como um vetor indicando quais observações devem ser usadas para estimar \(\alpha\). A função então fornece a estimativa para \(\alpha\) com base nas observações selecionadas.

alpha.fn <- function(data, index) {
 X <- data$X[index]
 Y <- data$Y[index]
 (var(Y) - cov(X, Y)) / (var(X) + var(Y) - 2 * cov(X, Y))
 }

Esta função retorna, ou fornece, uma estimativa para \(\alpha\) com base na aplicação de (5.7) às observações indexadas pelo argumento index. Por exemplo, o seguinte comando instrui o R a estimar \(\alpha\) usando todas as 100 observações.

alpha.fn(Portfolio, 1:100)
[1] 0.5758321

O próximo comando usa a função sample() para selecionar aleatoriamente 100 observações no intervalo de 1 a 100, com reposição. Isso é equivalente a construir um novo conjunto de dados bootstrap e recomputar \(\hat{\alpha}\) com base no novo conjunto de dados.

set.seed(7)

alpha.fn(Portfolio, sample(100, 100, replace = T))
[1] 0.5385326

Podemos implementar uma análise bootstrap realizando este comando várias vezes, registrando todas as estimativas correspondentes para \(\alpha\) e computando o desvio padrão resultante. No entanto, a função boot() automatiza essa abordagem. Abaixo, produzimos \(R = 1,000\) estimativas bootstrap para \(\alpha\).

boot(Portfolio, alpha.fn, R = 1000)

Call:
boot(data = Portfolio, statistic = alpha.fn, R = 1000)


Bootstrap Statistics :
     original       bias    std. error
t1* 0.5758321 0.0007959475  0.08969074

O resultado final mostra que, usando os dados originais, \(\hat{\alpha} = 0.5758\), e que a estimativa bootstrap para \(SE(\hat{\alpha})\) é 0.0897.

Estimando a Precisão de um Modelo de Regressão Linear

A abordagem bootstrap pode ser usada para avaliar a variabilidade das estimativas dos coeficientes e das previsões de um método de aprendizado estatístico. Aqui, usamos a abordagem bootstrap para avaliar a variabilidade das estimativas de \(\beta_0\) e \(\beta_1\), os termos de intercepto e inclinação do modelo de regressão linear que usa a potência do motor para prever o consumo de combustível (mpg) no conjunto de dados Auto. Compararemos as estimativas obtidas usando o bootstrap com aquelas obtidas usando as fórmulas para \(SE(\hat{\beta_0})\) e \(SE(\hat{\beta_1})\) descritas na Seção 3.1.2.

Primeiro, criamos uma função simples, boot.fn(), que recebe o conjunto de dados Auto, bem como um conjunto de índices para as observações, e retorna as estimativas de intercepto e inclinação para o modelo de regressão linear. Em seguida, aplicamos essa função ao conjunto completo de 392 observações para computar as estimativas de \(\beta_0\) e \(\beta_1\) em todo o conjunto de dados usando as fórmulas usuais de estimativa de coeficientes de regressão do Capítulo 3. Observe que não precisamos de { e } no início e no fim da função porque ela tem apenas uma linha.

boot.fn <- function(data, index)
  coef(lm(mpg ~ horsepower, data = data , subset = index))

boot.fn(Auto, 1:392)
(Intercept)  horsepower 
 39.9358610  -0.1578447

A função boot.fn() também pode ser usada para criar estimativas bootstrap para os termos de intercepto e inclinação ao amostrar aleatoriamente entre as observações com reposição. Aqui damos dois exemplos.

set.seed(1)

boot.fn(Auto, sample(392, 392, replace = T))
(Intercept)  horsepower 
 40.3404517  -0.1634868 
boot.fn(Auto, sample(392, 392 , replace = T))
(Intercept)  horsepower 
 40.1186906  -0.1577063

Em seguida, usamos a função boot() para computar os erros padrão de 1.000 estimativas bootstrap para os termos de intercepto e inclinação.

Como discutido na Seção 3.1.2, fórmulas padrão podem ser usadas para calcular os erros padrão para os coeficientes de regressão em um modelo linear. summary(lm(mpg ~horsepower, data = Auto))$coef

As estimativas de erro padrão para \(\hat{\beta_0}\) e \(\hat{\beta_1}\) obtidas usando as fórmulas da Seção 3.1.2 são 0.717 para o intercepto e 0.0064 para a inclinação. Curiosamente, essas são um pouco diferentes das estimativas obtidas usando o bootstrap. Isso indica um problema com o bootstrap? Na verdade, sugere o oposto. Lembre-se de que as fórmulas padrão dadas na Equação 3.8 na página 66 dependem de certas suposições. Por exemplo, elas dependem do parâmetro desconhecido \(\sigma^2\), a variância do erro. Estimamos \(\sigma^2\) usando o RSS. Agora, embora as fórmulas para os erros padrão não dependam da correção do modelo linear, a estimativa para \(\sigma^2\) sim. Vemos na Figura 3.8 na página 92 que há uma relação não linear nos dados, e assim os resíduos de um ajuste linear serão inflacionados, assim como \(\hat{\sigma}^2\). Em segundo lugar, as fórmulas padrão assumem (um tanto irrealisticamente) que os \(x_i\) são fixos, e toda a variabilidade vem da variação nos erros \(\epsilon_i\). A abordagem bootstrap não depende de nenhuma dessas suposições, e por isso é provável que esteja fornecendo uma estimativa mais precisa dos erros padrão de \(\hat{\beta_0}\) e \(\hat{\beta_1}\) do que a função summary().

Abaixo, computamos as estimativas de erro padrão bootstrap e as estimativas padrão de regressão linear que resultam do ajuste do modelo quadrático aos dados. Como esse modelo fornece um bom ajuste aos dados (Figura 3.8), agora há uma melhor correspondência entre as estimativas bootstrap e as estimativas padrão de \(SE(\hat{\beta_0})\), \(SE(\hat{\beta_1})\) e \(SE(\hat{\beta_2})\).

boot.fn <- function(data, index)
    coef(
        lm(mpg ~ horsepower + I(horsepower^2),
          data = data, subset = index)
)


set.seed(1)

boot(Auto, boot.fn, 1000)
